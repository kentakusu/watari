# 設計（案）

決まっていないものは「未決」と書く。★この文書は公開されている。特定のサービスの名前や中身を書かない（サイト固有のものは拡張に置き、拡張は別の場所に持てる）。

## 形

```
タスクトレイの渡（1 つ・ログオンで起動・常駐）
 ├─ 所属 A の Chrome（専用プロファイル 1 つ・ログインは所属で共有）
 │    ├─ セッション a1 の窓
 │    └─ セッション a2 の窓
 ├─ 所属 B の Chrome …
 └─ 拡張（フォルダごとに 1 つ）
各 Claude セッションの MCP サーバー → 127.0.0.1 で渡につながる
```

- セッションは `<所属>/<名前>` で識別する（[紡](https://github.com/kentakusu/tsumugi) を使うならその名前）。所属が Chrome（プロファイル）を、名前が窓を決める。
- ログインは所属で共有し、窓はセッションごとに分ける。同じ所属のセッションどうしが待たされずに同時に使える。
- Chrome は本物を CDP で操る（埋め込みのブラウザは Google 等がログインを拒むため使わない）。
- 窓は見える。人がログイン・2 段階認証をする。
- 背景の窓でも見張りが遅れないよう、起動時に背景の間引きを切る（`--disable-background-timer-throttling` 等。効き目は要実測）。

### 弱いところ
- ログイン状態は同じ所属の全セッションで共有される（1 つがログアウトすると全員に効く）。
- 同じアカウントを別の窓で同時に操作すると干渉するサイトがある。分けたいときは、そのセッションに専用のプロファイルを持たせる逃げ道を用意する。

## 窓の名札と「今触ってる」

- 窓の隅に小さな名札を出す（isolated world から shadow DOM で。サイトのスクリプトとは混ざらない）。名札の文字は Claude が決める。
- 名札に「今触ってる」ボタン。押している間、拡張と Claude の操作は止まって待つ（見張りは続ける）。
- 名札は畳める・動かせる（サイトのボタンを隠さないため）。

## 拡張

拡張は 1 つのフォルダ。宣言（どのサイト・何をきっかけに・何をして・誰に渡すか）とコード（JS/TS）を置く。

- 人の許可なしで入れて有効にしてよい（拡張は人の依頼を受けて入るので、許可は依頼の時点で済んでいる）。
- そのかわり、誰が・いつ入れたかを記録に残し、トレイから一覧と停止ができる。
- 宣言していないサイトの窓には、その拡張は触れない。
- 拡張を入れると、その拡張が持つ道具が MCP に現れ、外すと消える。

### 1 回の動き: DOM → ロジック → 操作 → 通知

1. **見張り**: 宣言したサイトの窓に、ページからは見えない別世界（isolated world）で `MutationObserver` を仕込む。宣言したセレクタの要素が変わったら、その要素の中身（テキスト・属性・必要なら outerHTML）を渡へ送る。
   - 値が変わったとき（例: バッジ 0 → 3）だけ送る。短時間の連続変化はまとめる。
2. **ロジック**: 拡張のコードが渡の中で動き、入力（その瞬間の DOM の値）から次にやることを決める。
3. **操作**: 要素をクリック（CDP の入力として送る＝人のクリックと同じ扱い）・文字を入れてボタンを押す・要素の中身を読む。
4. **通知**: 結果を紐づいたセッションの Claude へプッシュで渡す。

### 失敗は黙らせない
- 宣言したセレクタが見つからない（サイトの作りが変わった）ときは、通知で「見つからない」を知らせる。「何も来ていない」と区別できるようにする。
- 操作の前後で、狙った要素が在ったか・押したあと何が変わったかを記録に残す。

## 先に作った同種の道具から受け継ぐ考え方

コードは受け継がない。考え方だけ。

- **「0 件・緑・成功」を、「見ていない」と区別できる形で出す。** 生きているか（最後に成功した時刻・古いかどうか）を 1 か所に出し、Claude はまずそこを見る。
- **取りこぼしを数えて出す。** 番号が連番なら歯抜けを数える等、拡張が「漏れたかもしれない数」を出せる口を持つ。
- **見張りや操作が相手に副作用を出す**（開くだけで既読が付く等）。副作用を起こす操作は、確かめてから（記録に入ったのを見てから）行う。
- **止めすぎると逆に通信が増える。** 画面がつながっていないと判断して自分から取り直しを始めることがある。窓の通信を塞がない。
- **失敗した対象の扱いで、大事なものが遅れる。** 失敗後の待ちを一律に長くしない。大事なものだけ短く開き直し、続けて失敗したら長くする。
- **効かない取り直しを続けない。** 実際に効いたかを記録し、効いていないものは外す。
- **自分の失敗を記録する**（いつ・どこで・なぜ）。残さないと遅れの理由が推定になる。
- **起こす条件は安く速く**（語と宛先の印）。全部を AI に読ませない。外れは人が報告して条件を直す。
- **2 つの土台から同じファイルを触らない。** 触るなら錠と持ち主の名乗りで判別する。
- **土台（OS の更新・再起動）で静かに止まる。** 死活の監視を最初から作る。
- **相手への送信は最小に絞る。** 預けた宛先と本文に完全一致する 1 回だけを通し、毎回記録して確かめる。

### 渡の作りに効くもの
- **CDP をポートで開けない。** デバッグポートを開けたままにすると、同じ機械のほかのプロセスからもログイン中の窓を操れる。渡は Chrome を自分で起こすので、`--remote-debugging-pipe`（起こしたプロセスだけが話せる口）でつなぐ。**Windows で効くかは要実測。**
- **DOM は見せるための形。** 描かれていない行（仮想スクロール）は存在しないので、「描かれていない数」を数えて出す。画面に出るまでスクロールしないと中身を取りに行かない画面がある。
- **リッチエディタには、一般的な挿入命令が効かないことがある。** 入力はキー操作として送る（改行・削除のキーもサイトごとに違う）。拡張が入力の方法を選べるようにする。
- **背景の窓では入力が通らないことがある。** 「前面にある」と思わせる設定（CDP のフォーカスの模擬）を入れる。
- **自動の操作が人の画面を変える。** 窓を切り替えると書きかけが消える・戻し先がずれる。人の「今触ってる」の間は操作を止め、操作は短く終える。押したはずの対象と違うものが開いていたら、失敗として数え、副作用（既読など）を起こさない。
- **自分の操作の跳ね返り**（開き直すと通知がまた来る等）を、新しい出来事として数えない。
- **ログイン切れは「最後に画面から応答・変化が来た時刻」で古さとして見る。** 専用の検知は後で。時間帯でしきい値を変える（夜は静かなだけのことがある）。
- **死活の監視は渡の外から見る。** 渡が止まると中の見張りも止まるため。プロセスが居るか・最後の変化が古すぎないか・記録の更新時刻・OS の再起動後に起き直せたか。見張り自身の生存の印も出す。

## Claude へのプッシュ

- 第一案: 渡の MCP サーバーを Claude Code のチャネルにして、紐づいたセッションへ直接差し込む。**未検証。**要るもの:
  - 管理設定の `allowedChannelPlugins` に渡を足す（管理者権限・その機の全セッションに効く）。
  - セッションを `--channels` に渡を含めて起こす。
- 逃げ道: 紡の `tsumugi 届ける <名前>`（追加の設定なしで使える）。

## 作り（未決・本命あり）

| 候補 | 良い点 | 弱い点 |
|---|---|---|
| Electron（本命） | 拡張と同じ JS/TS で全部書ける。トレイ・設定画面・自動更新・配布の道具がそろう。Windows 以外もそのまま | 重い（RAM 100MB 前後・配布 100MB 超）。中の Chromium はブラウザとして使わない |
| Node ＋ 小さなトレイ部品 | 軽い | トレイの部品が外の実行ファイル頼み。配布が手作り |
| Tauri | 軽い | 芯が Rust になり、拡張（JS）と言語が分かれる |
| .NET | Windows で最も軽い | Windows 専用。拡張と言語が分かれる |

依存は少なく保つ。CDP の client は小さいので自分で書く。MCP は公式の SDK を使う。依存のライセンスは MIT / BSD / Apache-2.0 に限る（GPL 系は入れない）。

## 後回しにしたもの
- 通信（ネットワーク）の記録と、それを入力にする見張り。
- 操作の記録と再現（画面の操作として記録する案が先）。

## 最初に作る最小の形
所属 1 つ・窓 1 つ・DOM を見張る拡張 1 つ・`tsumugi 届ける` で通知。

### 実測したこと（2026-11-23・Windows 11・Chrome 158）
- `--remote-debugging-pipe` は Windows で効く。パイプで起こした Chrome のリッスンは 0 件・`DevToolsActivePort` も作られない（対照: `--remote-debugging-port=0` で起こすとリッスン 1 件・ファイルも在る）。
- 見張りを時間（200ms）でまとめると、「自分で既読にした直後に次の新着」のような 1→0→1 の往復が「変化なし」に潰れ、新着を落とした。いまは MutationObserver の変化の束ごとに見る。
- 見える窓で、見張り → 拡張 → `tsumugi 届ける` → 紐づいたセッションへのチャネルの届け、が端まで通った。

### まだ見ていないこと
- 背景・最小化の窓での遅れ（間引きを切る引数の効き目）。
- 本物のサイト（リッチエディタ・仮想スクロール）での入力と押下。
- ログイン切れの見え方。
